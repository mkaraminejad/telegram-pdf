## 🎯 چالش‌ها و راه‌حل این پروژه

تبدیل PDF فارسی به Word همواره با چالش‌های بزرگی روبه‌رو است:
* **وارونگی کلمات:** ابزارهای سنتی متن فارسی را به صورت دیداری (Visual) استخراج کرده و در ورد کلمات را از چپ‌به‌راست یا برعکس می‌چینند.
* **به‌هم‌ریختگی متون دوزبانه (BiDi):** ترکیب کلمات انگلیسی، شناسه‌ها، نسخه‌ها (مانند `Python 3.12`) و اعداد در جملات فارسی اغلب وارونه و نامنظم می‌شود.
* **حروف غیراستاندارد:** استفاده از «ي» و «ك» عربی به جای «ی» و «ک» فارسی و ارقام عربی در اسناد.
* **فقدان نیم‌فاصله:** جدا افتادن پیشوندهای «می/نمی» و پسوندهای «ها/ترین/خانه‌ام» و چسبیدن نامناسب عبارات.
* **مسدود شدن ربات تلگرام:** پردازش OCR چند صفحه‌ای بسیار سنگین است و نباید Event Loop ربات را قفل کند.

**راه‌حل این پروژه:**
این ربات با ترکیب خط‌لوله اختصاصی نرمال‌سازی نویسه‌های یونیکد، تفکیک هوشمند صفحات متنی و تصویری، پردازش ناهمگام در پس‌زمینه با صف Celery و تزریق مستقیم تگ‌های بومی OpenXML به ساختار درونی اسناد Word، خروجی‌های خوانا، قابل ویرایش و دقیق تولید می‌کند.

## ✨ ویژگی‌ها و قابلیت‌های کلیدی

### 🔤 ۱. موتور پردازش زبان و فونت فارسی
- **یکپارچه‌سازی نویسه‌های عربی به فارسی:** تصحیح خودکار کدهای یونیکد `\u0643` (ك) و `\u064A` (ي) به معادل‌های استاندارد فارسی.
- **تنظیم خودکار نیم‌فاصله‌ها (ZWNJ - `\u200C`):** 
  - پیشوندهای فعلی: «می‌رود»، «نمی‌دانم»، «بی‌توجهی»
  - پسوندهای جمع و صفات: «کتاب‌ها»، «مهم‌ترین»، «بهره‌مندی»
  - ضمایر متصل به «ه» غیرملفوظ: «خانه‌ام»، «نامه‌ات»، «جامعه‌شان»
- **استانداردسازی ارقام و تاریخ‌ها:** تبدیل ارقام عربی به فارسی با حفظ هوشمند اعداد درون آدرس‌های اینترنتی (URLs)، متغیرهای برنامه‌نویسی و مسیرها.
- **اصلاح نشانه‌گذاری:** تصحیح علامت سؤال فارسی (`؟`)، کاما و ویرگول فارسی (`،`) و جایگزینی گیومه‌ها با گیومه متقارن فارسی (`« »`).

### 📑 ۲. تفکیک هوشمند سند و OCR دوزبانه
- **استخراج مستقیم (Direct PDF Text):** اسناد متنی دیجیتال با سرعت بالا توسط کتابخانه بهینه PyMuPDF استخراج می‌شوند.
- **تشخیص صفحات اسکن‌شده (OCR Mode):** چنانچه صفحه‌ای فاقد لایه متنی باشد یا تراکم کاراکترهای آن اندک باشد، به طور خودکار به موتور **Tesseract OCR** با دیکشنری‌های `fas+eng` با وضوح تصویر بهینه (300 DPI) تحویل داده می‌شود.

### 📝 ۳. خروجی استاندارد Word با تگ‌های واقعی OpenXML
- برخلاف مبدل‌های سطحی که تنها جهت پاراگراف را راست‌چین (Right Align) می‌کنند، این سیستم خصوصیات بومی را در ساختار XML سند تزریق می‌نماید:
  - تگ `<w:bidi/>` در سطح مشخصات پاراگراف (`w:pPr`)
  - تگ `<w:rtl/>` در سطح ران‌های متنی (`w:rPr`)
  - تگ `<w:bidiVisual/>` در مشخصات جداول جهت ستون‌بندی راست‌به‌چپ
  - تعیین فونت فارسی استاندارد پیش‌فرض (Vazirmatn / B Nazanin) برای نمایش زیبا در تمام نسخه‌های Microsoft Word و LibreOffice.

### ⚡ ۴. معماری مقیاس‌پذیر و صف ناهمگام
- مستقل‌سازی فرآیند گوش‌دادن به پیام‌های تلگرام از فرآیند سنگین پردازش PDF.
- استفاده از **Celery** و **Redis**؛ پشتیبانی از اجرای چند Worker موازی با کنترل Concurrency.
- سیستم Deduplication برای جلوگیری از پردازش مضاعف یک آپدیت تلگرام حین قطعی‌های موقت شبکه.

### 🔒 ۵. امنیت، سادگی و حفظ حریم خصوصی
- بدون نیاز به پایگاه‌داده پیچیده خارجی یا ساخت پنل‌های اضافی غیرضروری.
- تخصیص دایرکتوری موقت با UUID ایزوله برای هر Task؛ ممانعت از تداخل و امکان حملات Path Traversal.
- حذف آنی فایل‌ها بلافاصله پس از ارسال به کاربر + تسک زمان‌بندی‌شده دوره‌ای برای پاکسازی فایل‌های جامانده حداکثر تا ۲۴ ساعت.
- گارد امنیتی چت تلگرام: ربات در گروه‌ها فعالیت نمی‌کند و کاربران را به چت خصوصی هدایت می‌کند.

## 🔄 جریان داده و خط‌لوله پردازش (Pipeline Diagram)

```
کاربر در تلگرام
   │
   │  ۱. ارسال فایل PDF
   ▼
[ aiogram 3 Dispatcher ]
   │
   ├── اعتبارسنجی فرمت (.pdf) و حجم (زیر 20MB)
   ├── کنترل نرخ درخواست (Rate Limit) و جلوگیری از تکرار (Deduplication)
   │
   │  ۲. پاسخ فوری به کاربر: «⏳ فایل دریافت شد؛ در حال تبدیل…»
   ▼
[ صف پیام Redis ]
   │
   │  ۳. دریافت تسک توسط Celery Worker در پس‌زمینه
   ▼
[ موتور استخراج و بازخوانی هوشمند سند ]
   │
   ├─► آیا موتور هوش مصنوعی (Google Gemini Multimodal Vision) فعال است؟
   │      ├─ [بله - حالت پیش‌فرض] ──► تحلیل بصری فریم‌های صفحه با هوش مصنوعی، رفع کامل وارونگی کلمات،
   │      │                          اتصال حروف بریده‌شده، و استخراج ساختاریافته تیترها و جداول
   │      └─ [خیر - حالت آفلاین]  ──► ارزیابی PyMuPDF و ارجاع صفحات تصویری به Tesseract OCR (fas+eng)
   ▼
[ خط‌لوله نرمال‌سازی و انطباق فارسی ]
   │
   ├── تبدیل «ي/ك» به «ی/ک» و ارقام عربی به فارسی
   ├── اعمال نیم‌فاصله هوشمند (ZWNJ) برای می/نمی، ها، ترین، ضمایر
   ├── تفکیک توالی‌های انگلیسی و عبارات دو زبانه (BiDi)
   └── اصلاح علائم نگارشی (گیومه « »، علامت سوال ؟، کاما ،)
   ▼
[ سازنده سند DOCX با OpenXML ]
   │
   ├── ایجاد سکشن و پاراگراف با خاصیت <w:bidi/>
   ├── ایجاد ران‌ها با جهت راست‌به‌چپ <w:rtl/> و فونت فارسی
   └── ذخیره فایل .docx نهایی در پوشه ایزوله موقت
   ▼
[ ارسال سند Word به تلگرام کاربر ]
   │
   │  ۴. تحویل فایل DOCX به کاربر همراه با گزارش تعداد صفحات
   ▼
[ پاکسازی دیسک ]
   └── حذف فوری فایل‌های موقت این Task از پوشه storage
```

## 🚀 راهنمای راه‌اندازی و استقرار

### روش ۱: استقرار با Docker Compose (پیشنهادی سرور)

این روش تمامی پیش‌نیازها اعم از Tesseract فارسی، Redis، Worker و Bot را بدون درگیری با نصب دستی پکیج‌های لینوکسی راه‌اندازی می‌کند:

```bash
# ۱. رفتن به مسیر پروژه
cd persian-pdf-bot

# ۲. ایجاد و ویرایش فایل .env
cp .env.example .env
nano .env  # توکن ربات تلگرام خود را وارد کنید

# ۳. بیلد و استقرار تمامی کانتینرها در پس‌زمینه
docker compose up -d --build

# ۴. بررسی سلامت و اجرای صحیح سرویس‌ها
docker compose ps

# ۵. مشاهده لاگ‌های جاری ربات و ورکر
docker compose logs -f bot
docker compose logs -f worker
```

برای متوقف ساختن یا راه‌اندازی مجدد:
```bash
# توقف سرویس‌ها
docker compose down

# ریستارت سرویس‌ها
docker compose restart
```

### روش ۲: اجرای محلی با محیط مجازی پایتون (توسعه و تست)

اگر قصد توسعه، تغییر کد یا دیباگ سریع روی ماشین محلی را دارید:

#### الف) نصب پیش‌نیازهای سیستمی:
* **روی Ubuntu / Debian:**
  ```bash
  sudo apt update
  sudo apt install -y python3-venv python3-pip tesseract-ocr tesseract-ocr-fas tesseract-ocr-eng poppler-utils redis-server
  ```
* **روی macOS (با Homebrew):**
  ```bash
  brew install python@3.12 tesseract tesseract-lang poppler redis
  ```

#### ب) راه‌اندازی و اجرای کدها:
```bash
# ۱. ساخت و فعال‌سازی Virtualenv
python3 -m venv venv
source venv/bin/activate

# ۲. نصب کتابخانه‌های پایتونی
pip install --upgrade pip
pip install -r requirements.txt

# ۳. آغاز به کار سرور Redis (در پس‌زمینه)
redis-server --daemonize yes

# ۴. اجرای ورکر Celery در یک تب ترمینال
celery -A bot.tasks.celery_app worker --loglevel=info --concurrency=2

# ۵. اجرای ربات تلگرام در ترمینال دوم
python -m bot.main
```

### روش ۳: استقرار به صورت سرویس Systemd لینوکس

برای سرورهای لینوکسی که بدون Docker مدیریت می‌شوند:

۱. فایل سرویس ورکر Celery را بسازید:
```ini
# /etc/systemd/system/persian-pdf-worker.service
[Unit]
Description=Persian PDF Celery Worker
After=network.target redis.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/persian-pdf-bot
EnvironmentFile=/opt/persian-pdf-bot/.env
ExecStart=/opt/persian-pdf-bot/venv/bin/celery -A bot.tasks.celery_app worker --loglevel=info
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

۲. فایل سرویس ربات تلگرام را بسازید:
```ini
# /etc/systemd/system/persian-pdf-bot.service
[Unit]
Description=Persian PDF Telegram Bot
After=network.target redis.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/persian-pdf-bot
EnvironmentFile=/opt/persian-pdf-bot/.env
ExecStart=/opt/persian-pdf-bot/venv/bin/python -m bot.main
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

۳. سرویس‌ها را فعال و روشن کنید:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now persian-pdf-worker
sudo systemctl enable --now persian-pdf-bot
sudo systemctl status persian-pdf-bot
```

### تنظیم پروکسی تلگرام (برای سرورهای دارای محدودیت اتصال)

در صورتی که سرور شما در موقعیتی قرار دارد که دسترسی به سرورهای تلگرام مسدود یا محدود است، می‌توانید از پروکسی HTTP/HTTPS یا SOCKS5 استفاده کنید. کافیست متغیرهای محیطی استاندارد را قبل از اجرای پایتون یا در فایل `.env` تنظیم کنید:

```ini
# نمونه تنظیم پروکسی در .env یا شل لینوکس:
HTTPS_PROXY=socks5://127.0.0.1:10808
HTTP_PROXY=socks5://127.0.0.1:10808
```
Aiogram 3 از این تنظیمات برای تمامی ارتباطات `aiohttp` به طور بومی استفاده خواهد کرد.

## 🤖 راهنمای گام‌به‌گام تلگرام و BotFather

۱. در تلگرام وارد ربات رسمی **[@BotFather](https://t.me/BotFather)** شوید.  
۲. دستور `/newbot` را ارسال کنید.  
۳. یک نام نمایشی برای ربات بنویسید (مثلاً: `مبدل PDF فارسی به Word`).  
۴. یک نام‌کاربری یکتا انتخاب کنید که به کلمه `bot` ختم شود (مثلاً: `PersianPdfToDocx_Bot`).  
۵. توکن ارائه‌شده را در فایل `.env` جلوی `TELEGRAM_BOT_TOKEN` کپی کنید.  
۶. **تنظیم دستورات در منوی تلگرام:** دستور `/setcommands` را در BotFather بزنید و لیست زیر را وارد کنید:
```text
start - راهنمای شروع و پیام خوش‌آمدگویی
help - راهنمای جامع شرایط فایل‌ها و محدودیت‌ها
status - وضعیت سلامت سیستم، موتور OCR و محدودیت‌ها
```
۷. **افزایش امنیت (غیرفعال کردن اد در گروه‌ها):**  
دستور `/setjoingroups` را به BotFather ارسال کرده و وضعیت آن را روی **Disable** بگذارید تا ربات تنها در پیوی امن کاربران به فعالیت بپردازد.

## 🖋️ قواعد خط‌لوله استانداردسازی فارسی و OpenXML

### الف) جدول تبدیل نویسه‌های عربی به فارسی
| نویسه خام عربی | کد یونیکد | نویسه اصلاح‌شده فارسی | کد یونیکد |
| :---: | :---: | :---: | :---: |
| ك | `\u0643` | ک | `\u06A9` |
| ي | `\u064A` | ی | `\u06CC` |
| ى | `\u0649` | ی | `\u06CC` |
| ة | `\u0629` | ه | `\u0647` |
| ۀ | `\u06C0` | ه‌ی | `\u0647\u200C\u06CC` |

### ب) قوانین نیم‌فاصله خودکار (ZWNJ)
* **پیشوندها:** اتصال خودکار پیشوندهای «می»، «نمی» و «بی» به کلمه بعد (مثال: `می رود` ⬅️ `می‌رود`).
* **پسوندها:** اتصال نیم‌فاصله‌ای پسوندهای «ها»، «های»، «ترین»، «تر»، «مند»، «پذیر»، «شناس» (مثال: `کتاب ها` ⬅️ `کتاب‌ها`).
* **ضمایر کلمات مختوم به ه غیرملفوظ:** تصحیح «ام/ات/اش/ایم/اید/اند» (مثال: `خانه ام` ⬅️ `خانه‌ام`).

### ج) تگ‌های درونی ساختار Word OpenXML
برای اطمینان از این‌که نرم‌افزار Word در کامپیوتر یا موبایل متن را بدون درهم‌ریختگی و وارونگی نمایش دهد، ماژول `docx_builder.py` تگ‌های زیر را به درخت XML سند تزریق می‌کند:

```xml
<!-- راست‌به‌چپ کردن پاراگراف در سطح ساختار -->
<w:pPr>
  <w:jc w:val="right"/>
  <w:bidi/>
</w:pPr>

<!-- اعمال خصوصیات فونت فارسی و جهت ران‌های متنی -->
<w:rPr>
  <w:rtl/>
  <w:rFonts w:ascii="Vazirmatn" w:hAnsi="Vazirmatn" w:cs="Vazirmatn"/>
  <w:sz w:val="24"/>
</w:rPr>

<!-- در صورت وجود جدول: تنظیم ترتیب ستون‌ها از راست به چپ -->
<w:tblPr>
  <w:jc w:val="right"/>
  <w:bidiVisual/>
</w:tblPr>
```

## ❓ عیب‌یابی و پرسش‌های متداول (FAQ)

### ۱. ربات به پیام‌های ارسالی من در تلگرام پاسخ نمی‌دهد؛ علت چیست؟
- ابتدا مطمئن شوید توکن `TELEGRAM_BOT_TOKEN` درون فایل `.env` به درستی ثبت شده و با دستور `docker compose logs -f bot` خروجی را مشاهده فرمایید.
- بررسی کنید سرور به سرورهای تلگرام دسترسی دارد یا نیاز به تعریف پروکسی (`HTTPS_PROXY`) دارد.

### ۲. در فایل ورد دانلود شده، جهت کلمات در نسخه‌های قدیمی آفیس چپ‌به‌راست است؟
- تگ‌های OpenXML اعمال‌شده (`<w:bidi/>`) بالاترین استاندارد مایکروسافت ورد هستند. اطمینان حاصل فرمایید در Word فونت متناسب فارسی (نظیر `Vazirmatn` یا `B Nazanin`) روی سیستم فعال است.

### ۳. کیفیت متن استخراج‌شده از فایلی که دست‌نویس یا اسکن تار بوده پایین است؟
- موتور Tesseract OCR بر پایه تصاویر تایپ‌شده ۳۰۰ DPI آموزش دیده است. متن‌های اسکن‌شده کم‌کفیت یا دست‌نویس ذاتا توسط موتورهای استاندارد OCR با خطای تشخیصی مواجه می‌شوند. پیشنهاد می‌شود کاربر اسناد را با زاویه صاف و نور کافی اسکن کند.

### ۴. برای افزایش ظرفیت پردازش هم‌زمان چه تنظیمی وجود دارد؟
- در دستور اجرای Celery می‌توانید پارامتر `--concurrency=4` یا `--concurrency=8` را متناسب با تعداد هسته‌های CPU سرور خود افزایش دهید.

## 🛡️ امنیت، حریم خصوصی و نگهداری

* **جداسازی کامل تسک‌ها (Isolation):** هر فایل پس از ورود، در یک پوشه موقت اختصاصی به آدرس `/app/data/temp/<task_uuid>/` قرار می‌گیرد.
* **ضد Path Traversal:** نام فایل‌های ورودی فیلتر شده و کاراکترهای خطرناک نظیر `../` پاکسازی می‌شوند.
* **عدم ذخیره متون در لاگ:** لاگ‌های برنامه فقط شناسه چت و حجم فایل را ثبت می‌کنند و هرگز متون داخل اسناد در فایل‌های لاگ درج نمی‌شوند.
* **پاکسازی ۲۴ ساعته خودکار:** حتی در صورت بروز خطای اضطراری یا کرش ناگهانی، فرآیند زمان‌بندی‌شده دوره‌ای هر ساعت دیسک را بررسی و فایل‌های مانده از ۲۴ ساعت پیش را به طور قطعی پاک می‌کند.
